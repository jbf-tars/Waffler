# Waffler roadmap: the "polished dictation" layer (on 3.15.1)

Date: 2026-10-16. Base: `origin/main` at v3.15.1. Branch: `feature/parity-on-3.15`.

An earlier draft of this roadmap was written against v3.14.69 and partly duplicated work that 3.15 already shipped. This version replaces it. The old branch `feature/wispr-parity` is kept only as a source of code to port.

## Goal

Waffler's core (hotkey, Whisper, LLM clean-up, paste) is strong, and 3.15 added a new design, a persistent setup, a recent-audio buffer, quiet-audio lift, "sounds like" vocabulary and a processing watchdog. What is still missing is the layer around the core that the best commercial dictation apps have: pasting that does not clobber the clipboard, per-app tone, edit-by-voice, a usable Snippets editor, richer stats, and a few small touches that make the app feel finished.

## Non-goals

No hosted backend, accounts, sync, analytics, teams, billing, leaderboards, meeting notes, IDE plug-ins or headset integrations. Waffler stays bring-your-own-key: audio and text go only to the provider the user configured.

## What 3.15.1 already has (do not rebuild)

Start at login; persistent first-run setup with a live mic meter; Retry on "Not sent" cards and a last-10 recordings buffer (`recent_audio.py`, `unsent.py`); quiet-audio lift (`quality.py`); a processing watchdog (`pipeline_watchdog.py`, `pipeline_policy.py`); a custom hotkey recorder with Fn conflict handling; day-count history retention and a Privacy and data page (`privacy_data.py`); paged, cached Journal on `history.json` (`journal_data.py`, `atomic_json.py`); "sounds like" vocabulary with derived usage counts and a log-mining migration; Groq clean-up on `openai/gpt-oss-120b` with cooldowns; 85 test files (1,298 tests) enforced in CI, including AST scanners for file encoding and safe writes and a pinned SELF-CORRECTION prompt section.

## Dropped or deferred, and why

| Item | Why |
|---|---|
| SQLite history database | JSON is fast enough (4.5 ms parse at 5,000 entries) and is wired into the Journal, retention, Not-sent cards and ~140 tests. Revisit at ~25k entries or if an append exceeds 150 ms on Windows. |
| "Medium" clean-up level | Contradicts the maintainer's rule that a silent deletion is worse than an uncorrected paste. Deferred. Only **Off** and today's behaviour ship. |
| Re-enabling `prompts/email.txt` | Its permissive paragraphs contradict a rule added after a production failure. Email handling stays in `normal.txt`. |
| Replacement rules in the dictionary | "Sounds like" spellings already are replacement rules. |
| Persistent onboarding, start at login | Shipped in 3.15. |
| A fourth "Insights" page | Navigation is three tested pages. Stats go to Settings > Usage and the Journal rail. |
| Time-based audio retention (14 days / 24 h) | Settings promises "last 10 recordings"; a time window changes that promise. |
| Chunk-in-flight transcription | 3.14.71 to 3.14.97 showed duration-based chunking caused truncation. Only the cap rises (12 to 20 minutes) using the existing size-triggered splitter. |
| Writing samples for transforms, nine transform hotkeys, voice notes | Token cost on a free tier that allows about 30 clean-ups a day. Voice notes stay low priority. |

## Conventions every change must follow (maintainer rules, enforced by tests)

1. **Prompts.** `prompts/normal.txt` is formatted with only `{transcript}` and `{dialect_instruction}`. New instructions (language, style) go into the value of `dialect_instruction`. Default settings must produce a byte-identical prompt (unit-test it). The SELF-CORRECTION section is SHA-256 pinned; any other prompt edit needs the 107-case corpus.
2. **Never lose words silently.** Anything that can shorten text needs its own provider tag and quality threshold so Journal chips stay honest.
3. **Settings.** Read with `_load_settings_file()`, write through `Api._editing_settings()`. `get_settings` and `save_settings` list keys explicitly: add each new key to both, with validation, plus UI.
4. **Files.** Use `data_paths.data_dir()` at call time; atomic JSON helpers for writes; always pass an encoding (a scanner fails `open`/`read_text`/`write_text` without one); register every new data file in `privacy_data.DATA_FILES` / `DATA_FOLDERS`, the log-download exclusions and the Privacy copy.
5. **Messages.** Plain sentences in `user_messages.py`, no raw errors, no em dashes; toast actions go through `_on_toast_action`.
6. **UI.** Atelier design system (`tokens.css`, `components.css`, `setup.css`, `logic.js`): sentence case, line icons, contrast and tab-stop rules policed by tests. UI logic that can be pure lives in `logic.js` and is unit tested.
7. **Pipeline.** Every blocking step goes through `run.call` under the watchdog; no clipboard reads on timers; history writes through `append_history_safely`; `tests/_pipeline_harness.py` lifts named methods out of `app.py`, so a new helper called from `_process` must be added to its lists.
8. **Cross-platform.** macOS first. Mac-only code is guarded, Mac-only tests skip on Windows (Windows CI runs the full suite). CI uses Python 3.11.
9. **Privacy.** No transcript text in logs (use `transcript_for_log`); no new network destinations beyond the user's chosen provider (plus a search engine URL opened in the browser for "ask the web").

## Work packages (in dependency order)

**S1 Quick fixes.** Language picker (`src/languages.py` ported; rule fed through `dialect_instruction`; Atelier row; validation). Groq robustness: advance to the next model on "model gone" errors, give a retired model its own message (today it shows a fake "paused for an hour" rate limit), fix the OpenAI-first short-circuit that skips Groq and Cerebras. Snippets: rebuild the editor on the Vocabulary page; whole-utterance match; longest-first whole-word matching.

**S2 Safe paste.** Port `pasteboard.py` and `mac_input.py`; one `paste_text` through the watchdog with an outcome (`pasted`, `unverified`, `failed`); restore the previous clipboard (Mac only, setting `clipboard_after_paste`, default restore); failed paste leaves the text on the clipboard with a toast; "Paste last" and "Copy last" in the menu bar (show a word count, not a text preview); permission pre-check at key-down including a tap-alive check.

**S3 Notifier, sounds, hints.** One governor for the ~18 ad hoc toast sites (caps, minimum gaps, dismissal memory, one slot at a time, errors pre-empt tips); optional sounds; a quiet "Don't tap, hold" hint (once per 12 hours).

**S4 History details.** Optional `id` and metadata on entries (`duration_s`, `speech_s`, language, provider, paste outcome, app name); per-item delete; export as JSON/CSV/text; link an entry to its recent-audio file for "Redo this take"; crash marker so an interrupted take becomes a recoverable card; `usage.json` append-only fix (it is rewritten twice per dictation before the paste).

**S5 Context and shared LLM path.** `text_context.py` (frontmost app bundle and name, selected text via Accessibility with a clipboard-copy fallback) and `app_categories.py`; capture the target at hotkey press; one `_chat()` in the styler replacing three divergent bodies (state passed as arguments, not stored on `self`).

**S6 Style layer.** Clean-up Off switch; four styles implemented as deterministic code in `style_post.py` (case, final period, greeting break) with a prompt line only where unavoidable (Excited); per-category choices; opt-in email signature; a Settings section.

**S7 Transforms.** Selected-text Polish (rule checkboxes) and Prompt Engineer, a few user-defined transforms, an in-window Journal diff with Undo/Copy/Retry and overlay toast buttons (no new window), local-only.

**S8 Command mode.** Hold-to-talk instruction applied to the selection or "ask the web" (opens the chosen engine); tagged first line instead of JSON mode. Off by default, labelled beta.

**S9 Stats.** Week streak, peak hour, heatmap, week versus last, minutes saved, words per minute (from `speech_s` for new entries, backfilled from `quality.jsonl`), top app: pure additions to `compute_stats`, shown in Settings > Usage and the Journal rail.

**S10 Dictionary and snippets v2.** Vocabulary search, sort and multi-select; CSV import and export; starred entries (low priority); auto-learn from a Journal edit (sounds-like must be Whisper's spelling, not the styler's); Snippet import and export.

**S11 Shortcuts and long takes.** Cap 12 to 20 minutes via the existing splitter; one editor with an action row per shortcut (hands-free, cancel, paste last, transform, command), cross-action conflict warnings, tap-versus-hold and double-tap; optional extra mouse buttons.

**S12 Microphones and Flow Bar.** Ranked mic list by name and id, "use this mic?" prompt on hot-plug, early silence watchdog (5 s and 15 s) with one automatic re-open, follow-system when no mic is saved (today an explicit index is pinned), a small Flow Bar hover menu and remembered position.

## Verification

Each package ends with: new pytest tests, the full suite green (`python -m pytest tests -q`, baseline 1,298 passed and 13 skipped), `scripts/check_doc_drift.py`, pyflakes not above baseline, the import-every-module check, a CHANGELOG entry under `[Unreleased]`, and a local commit. Live provider checks for anything that changes a prompt or model. UI checked in a browser with a stubbed `pywebview.api`. Behaviour that needs real permissions (Accessibility reads, pasting into other apps, event taps, multi-display) is tested as far as this process allows and reported as unverified in a real session. Nothing is pushed, tagged or released.


## Settings added

Each package that adds a settings key records its shape here, so the shortcut editor (S11) and the next package find them in one place.

### S7 Transforms (beta)

One key in `settings.json`, `transforms`, an object. It is read with `transforms.settings(stored)` (every key present, anything unreadable the default) and written only through `save_settings({"transforms": {...}})`, which checks the whole payload first (`transforms.settings_problem`) and merges it (`transforms.merged`); a refused payload saves none of what came with it. A save names only the parts it changes. `get_settings()["transforms"]` is `transforms.window_view(stored)`: the same shape, plus `skeleton_default` and `hotkey_display`.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `enabled` | bool | `false` | The whole feature. Off: no shortcut is registered, the menu item is hidden, a start request is ignored. |
| `hotkey` | list of key names | `[]` | The Transform shortcut as the hotkey recorder names the keys (Mac: `control`, `option`, `shift`, `cmd`; Windows: `win`, `ctrl`, `alt`, `shift`; then one letter, digit or F key). Checked by `action_hotkeys.check`: one non-modifier key, at least two modifiers including Control or Command (Control or the Windows key on Windows), no Fn, nothing reserved, no overlap with `hotkey_keys`, nothing another action uses. Stored in the canonical order. Also saved through `Api.save_transform_hotkey(keys)` (the window's recorder). |
| `default` | str | `"polish"` | Which transform the shortcut and the menu item run: `polish`, `prompt_engineer` or the `id` of one of `custom`. A value that is not there reads as `polish`; deleting the chosen transform resets it. |
| `polish.rules` | `{key: bool}` | the defaults in `transforms.POLISH_RULES` (`grammar`, `clarity`, `tone`, `sentences`, `paragraphs` on; `structure`, `concise` off) | Unknown names are refused. At least one rule (or one of `custom_rules`) must stay on. |
| `polish.custom_rules` | list of str | `[]` | Up to 5 one-line rules, 160 characters each, no duplicates. |
| `prompt_engineer.skeleton` | str | `""` | The outline Prompt Engineer fills in, up to 1,200 characters. `""` means the built-in outline (`transforms.DEFAULT_SKELETON`); a save of the built-in text is stored as `""`, so a better built-in reaches whoever never changed it. |
| `custom` | list of `{id, name, prompt}` | `[]` | Up to 5. `name` up to 40 characters, unique (any case), not "Polish" or "Prompt Engineer"; `prompt` up to 800. `id` is made by Waffler (`[a-z0-9_]{1,16}`); a name that was there keeps its id. |

Related, added with it:

- The answer is checked before it replaces anything (`transforms.finish`): the same text back is "no change"; under 30 percent of the words (10 percent for a `custom` transform, whose job may be to shorten), over 2.5 times the words (or 30 more; 300 more for Prompt Engineer and `custom`), an answer the model said it cut off, or (Polish, five words or more) one that shares under a quarter of the wording, replaces nothing. Lengths count half a word per character of a script written without spaces.
- Journal entries of `kind: "transform"` (`before`, `after`, `transform_id`, `transform_name`, `provider: {"transform": ...}`, `model`, `took_s`, plus the usual `app`, `app_bundle`, `category`, `paste`, `lang`). They have no `text` or `styled`, and `journal_data.compute_stats` counts them in `entries` and `transform_count` only. See `history_meta.py`.
- Usage rows may carry `purpose: "transform"` (still `type: "gpt"`, priced as any call); `get_usage_stats` leaves them out of "about X a dictation" and adds `transform_count` and `transform_cost_usd`.
- Notifier kinds `transform_result`, `transform_busy` (a gap of 8 s), `transform_failed`; toast action `show_transform:<entry id>`.
- Logs bundle: `privacy_data.settings_for_logs` replaces the wording of `polish.custom_rules`, `prompt_engineer.skeleton` and `custom` with lengths.
- `Api.save_hotkey_config` refuses a dictation hotkey that overlaps `transforms.hotkey` (`action_hotkeys.dictation_clash_message`).

For S11: `src/action_hotkeys.py` keeps the shortcuts of actions in one registry (`register(action_id, keys, callback, dictation_hotkey)`, `unregister`, `conflict`, `registered`); Transform is the action `"transform"`. The Mac listener is a handler on the dictation hotkey's one event tap (`SmartHotkeyListener.attach_observer`), because a second tap crashed the process (src/mac_hotkey_monitor.py); Windows has a hook of its own.

### S8 Command mode (beta)

One key in `settings.json`, `command_mode`, an object. It is read with `command_mode.settings(stored)` (every key present, anything unreadable the default) and written only through `save_settings({"command_mode": {...}})`, which checks the whole payload first (`command_mode.settings_problem`) and merges it (`command_mode.merged`); a refused payload saves none of what came with it. A save names only the parts it changes. `get_settings()["command_mode"]` is `command_mode.window_view(stored)`: the same shape, plus `hotkey_display`.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `enabled` | bool | `false` | The whole feature. Off: no shortcut is registered and a key-down is ignored. |
| `hotkey` | list of key names | `[]` | The hold-to-talk shortcut, named as the hotkey recorder names keys (the same names and rules as `transforms.hotkey`, checked by `action_hotkeys.check`: one non-modifier key, at least two modifiers including Control or Command, no Fn, nothing reserved). It may not overlap `hotkey_keys`, the Transform shortcut (equal, or the same key with more or fewer modifiers), or anything else registered. As a hold it may also not be Ctrl and Alt together (without the Windows key) on Windows, where that is AltGr on many keyboards and would type the letter while held (`check(..., hold=True)`). Stored in the canonical order. Also saved through `Api.save_command_hotkey(keys)` (the window's recorder). |
| `web_engine` | str | `"perplexity"` | Where a spoken question opens: `perplexity`, `google`, `duckduckgo`, `chatgpt` or `claude` (`command_mode.ENGINES`; anything else is refused on save and reads as Perplexity). |

Related, added with it:

- The shortcut is a hold: `action_hotkeys.ActionHotkeys.register_hold(action_id, keys, on_down, on_up, dictation_hotkey)`. `on_down` runs when the combination goes down, `on_up` when any part of it comes up (the key, or any one modifier: `key_up`, `modifiers_changed` on a Mac's flags-changed events, `modifier_up` from the Windows hook). The two run in order on a thread of the action's own. A hold that never got its key-up is ended after `HOLD_STALE_S` (120 s) so the next press is a press. The Mac observer ignores events Waffler posted itself (the source process id). Action ids in use: `"transform"` (a press) and `"command"` (a hold). `check` now also refuses the same key with more or fewer modifiers than another action (`That overlaps another shortcut...`), and `action_hotkeys.saved_shortcuts(stored)` reads both saved shortcuts for the checks in `transforms.settings_problem`, `command_mode.settings_problem` and `save_hotkey_config`.
- The run is `src/command_action.py`, its own `CommandRunner` (not `_process`): at key-down it notes the app and starts the recorder, reads the selection through Accessibility (no keystroke) or, with nothing selected, up to 500 characters before the cursor; on letting go it stops the recorder, reads the selection by Copy if Accessibility could not (never while the keys are down), turns the speech into text with the existing speech call (vocabulary applies, no clean-up, snippets or style) and makes one `_chat()` call with `purpose="command"`. 30 seconds in all from letting go; the hold itself is capped at 60 seconds in case a key-up never comes. Esc and the pill's X cancel it until the paste begins (`_on_hotkey_cancel`, `_on_overlay_cancel`).
- The model's first line is `ACTION: edit`, `ACTION: draft` or `ACTION: ask`, then the result. `command_mode.parse_reply` is tolerant (case, spacing, markup, fences, JSON by mistake, a short lead-in before the tag; with no tag it guesses: text selected, an edit; a question, a search; otherwise a draft, and a guessed edit must still share a quarter of the selection's wording). An edit with nothing selected is a draft. A draft never replaces a selection: with text selected it is put on the clipboard. A search opens `command_mode.search_url(engine, question)`: only words the person said aloud (`command_mode.ask_query`), never the selection or the context.
- Journal entries of `kind: "command"` (`action`, `instruction`, `before` for an edit, `after` for an edit or a draft, `query` and `engine` for a search, `provider: {"command": ...}`, `model`, `took_s`, plus the usual `app`, `app_bundle`, `category`, `paste`, `lang`). They have no `text` or `styled` and no `audio`. `history_meta.NON_DICTATION_KINDS` (`transform`, `command`) is the one list the numbers, search, "Paste last" and Redo read; `journal_data.compute_stats` counts a command in `entries` and `command_count` only.
- Usage rows carry `purpose: "command"` (the model call as `type: "gpt"`, the speech as `type: "whisper"`); `get_usage_stats` leaves them out of "about X a dictation" and of `transcription_count`, and adds `command_count` and `command_cost_usd`.
- Notifier kinds `command_result`, `command_busy` (a gap of 8 s), `command_failed`; toast action `show_command:<entry id>`. The dictation hotkey, a transform and a second command are refused while one runs, and a command is refused during any of them.
- No new data file, menu item or tray item. The settings are not secret and go into the logs bundle as they are.


### S9 Stats

One key in `settings.json`, `typing_wpm`, a whole number from 10 to 200 (40 until set). It is read with `stats_insights.typing_wpm_of(stored)` (anything unreadable is 40) and written through `save_settings({"typing_wpm": n})`, which refuses anything else (`user_messages.TYPING_SPEED_UNKNOWN`) before saving any of the payload. `get_settings()["typing_wpm"]` is the same number. It only feeds the minutes-saved estimate; `HistoryCache` reads it through a function (`app._typing_wpm_setting`) on each `stats()` call and keys its cache on it, so a change shows at once with no new read of `history.json`.

New keys of `journal_data.compute_stats` / `get_stats` (all optional for old entries, all computed in the one walk by `src/stats_insights.py`; the old keys are unchanged). Entries that are `failed` (Not sent) or of `kind` `transform` / `command` are in none of them.

- `today`, `weekday`: the local date the figures were worked out for, and its weekday (0 = Monday).
- `week_streak`: consecutive Monday-to-Sunday weeks with a dictation, ending this week, or last week while this week has none yet.
- `words_this_week`, `words_last_week`, `words_last_week_same_days`, `week_change_pct`: this week so far; the whole week before; the days of last week that this week has had so far (all of it on a Sunday); the change between the first and the third as a whole percent (half away from zero), `None` when those days had no words.
- `words_this_month`: `month_words` under the week figures' name.
- `peak_hour`, `hour_counts`, `peak_hour_needs`: the local hour (0 to 23) with most dictations (the earlier on a tie), `None` until 20 dictations have a time; the 24 counts; the 20.
- `heatmap`: `{start, weeks: 26, days: [[7 words or None] x 26], max}`, Monday-first columns from the Monday of the week 25 weeks back; days after today are `None`.
- `minutes_saved`, `minutes_saved_basis`: an estimate. Words / `typing_wpm` less the time to say them (`duration_s`, never faster than 300 words a minute, else 150 words a minute), summed over dictations (a long recording counts against a short one), never below 0. The basis has `typing_wpm`, `words`, `typing_minutes`, `speaking_minutes`, `timed`, `estimated`.
- `wpm`, `wpm_samples`: words said over seconds of speech for the latest 100 usable dictations (`speech_s`, else `quality.jsonl`'s by timestamp; 3 words or more, 1 s or more, 20 to 400 a minute); `None` until 10.
- `top_apps`, `apps_recorded`, `apps_not_recorded`, `apps_total`: the five apps with most dictations (`app`, else `app_bundle`; case and spacing ignored), and the dictations that name none.

Days and hours come from the entry's stamp (local wall-clock time) and every step between days is on the calendar, so a clock change cannot move a day. `local_today(now, tz)` is the one place a zone matters; `HistoryCache(..., clock=, tz=)` take them for `stats()` with no day. The window reads these with the pure helpers in `ui/logic.js` (`weekView`, `weekStreakView`, `wpmView`, `minutesSavedView`, `peakHourView`, `topAppsView`, `heatmapView`, `heatMove`, `typingSpeedCheck`). No new data file, nav page, network call or log line.

### S10 Vocabulary and Snippets v2

One key in `settings.json`, `learn_from_edits`, a bool. It is read as on unless it is exactly `false` (`learn_words.enabled(stored)`) and written through `save_settings({"learn_from_edits": bool})`, which refuses anything else (`user_messages.LEARN_FROM_EDITS_UNKNOWN`) before saving any of the payload. `get_settings()["learn_from_edits"]` is the same bool. It only decides whether `edit_history_text` computes suggestions; nothing is ever added without a click. It is not secret and goes into the logs bundle as it is.

Meaning: the Vocabulary page's "Suggest words from my edits", default `true`. Off: `edit_history_text` still keeps the edit and returns no suggestions.

New data, all optional and invisible to Waffler 3.15.1 (a downgrade loses nothing):

- `vocab_stars.json`, a list of the starred words, read against the words listed now (any capitals), written with `write_json_atomic` through `vocab_rank.sync_stars` after every `set_vocab` (pruned when a word is gone). It is a separate file because `vocab.json` is the plain list of strings that 3.15.1 and 3.14 read; an entry that is an object there is dropped by `clean_vocab`, and the word lost. It is in `privacy_data.KEPT_FILES` (kept by Delete all my data, removed with the folder by the full reset) and in the logs bundle beside `vocab.json`. A star changes only the page's order and the prompt below.
- `edited_text` on a Journal entry (a dictation only): what the person made of it (`history_edit`). `styled` and `text` are not touched, `word_count` and the stats still measure what was dictated. `history_meta.final_text(entry)` is the words to show, copy and paste again; the card, Copy, `LastResult` (Paste last, Copy last, also after a restart), the Journal search and the CSV and text exports read it, the JSON export keeps both texts, Redo this take drops it (`KEPT_ON_REDO`), deleting and retention treat the entry as before. `Api.edit_history_text(item_id, timestamp, text, new_text)` finds the entry as `delete_history_item` does and returns `{ok, state: edited | cleared | unchanged, item, suggestions}`; saving the pasted text again removes the field.
- Exports are files on the Desktop (`waffler-vocabulary-<time>.csv`, `waffler-snippets-<time>.csv|json`) written by `export_files.save`, the person's own copies, never touched by Delete all my data.

The prompt (OpenAI and local only; Groq still gets none): `transcribe_whisper.vocab_prompt_hint(vocab)` calls `vocab_rank.prompt_words(words, stars, usage)`. When the whole list fits (at most `PROMPT_MAX_ENTRIES` = 80 words and `PROMPT_MAX_CHARS` = 700 characters with their separators) it is sent in list order with the starred words first, which for no stars is byte-identical to `vocab_to_prompt`. Otherwise: starred, then most corrections (derived from the Journal through `transcribe_whisper.set_vocab_usage_source`, set by app.py, read only when the list has to be cut, and an unreadable one ranks nobody), then the list's own order, cut at the caps. The list cap of 500 words is unchanged. The ranking falls back to the whole list if it raises.

Import and export:

- `table_io` reads what Excel, Numbers and Google Sheets write: UTF-8 with or without a byte order mark, UTF-16, Windows-1252; a comma, semicolon or tab (`sep=` line understood); quotes, doubled quotes and line breaks in a cell; at most 2,000,000 characters and 5,000 rows. It writes with CRLF, a UTF-8 byte order mark, and a `'` in front of any cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return (`defuse`, the same rule as the Journal export); import removes exactly that mark (`undefuse`), so an export imports unchanged.
- `dictionary` (Vocabulary): columns `word`, `sounds_like` (separated by semicolons; commas, bars and line breaks also split on import), `starred` (yes or no); headers are matched by name in any order or absent (then word, spellings, star). `plan_import(parsed, words, sounds, starred)` only adds: a word is checked by `check_word` (not empty, up to 60 characters, no control or invisible character other than a zero-width joiner, a letter in it), the list has room (500), and an everyday word (`transcribe_whisper.is_everyday_entry`) needs a spelling; a word already there keeps its place and spelling and only gains spellings and a star; each spelling is held to the sounds-like rules (60 characters, a letter or digit, not the word, not another word, not already taken, 8 a word) and listed when left out; the same word on several rows is one entry. It returns the preview (`preview_view`: counts, the first 30 names, the first 50 rows left out with row number and reason) and the lists as they would be. The by-hand add is unchanged: `set_vocab` does not apply `check_word`.
- `snippets_io` (Snippets): CSV `trigger,expansion` or the `snippets.json` shape as JSON; the same limits as the editor (60, 4,000, 200); a trigger already there (any capitals) keeps its text and the row is listed as left out (`exists`), unless the text is the same (`already`); the same trigger twice in the file keeps the first row.
- Bridge: `export_vocabulary()`, `preview_vocab_import(content, is_base64)`, `import_vocabulary(content, is_base64)` (answers `before`, the lists as they were, for the page's Undo, which is `set_vocab(before.words, before.sounds_like, before.starred)`), `export_snippets(fmt)`, `preview_snippets_import`, `import_snippets` (Undo is `set_snippets(before)`). A preview saves nothing. `set_vocab(words, sounds_like=None, starred=None)`: `starred` replaces the stars, left out it keeps those of the words still listed; the answer carries `starred`. `get_vocab_book()` carries a top-level `starred` list (the entries keep their old shape).
- The page reads a chosen file as bytes and sends base64 (`is_base64`) so the app decodes it; a paste box always works, since a web view may not offer a file picker.

Suggestions (`learn_words.suggest(heard_text, pasted_text, edited_text, words, sounds_like)`, no model, nothing added): words are compared with case, punctuation and line breaks ignored; a candidate is one word that became one other word (a 1 to 1 replace), or the same word whose capitals say something (an interior capital, or a capital that is not at the start of a sentence); at least three letters, `check_word` clean, not an everyday word, not already a word or a "sounds like"; a new word without a capital must also share 72 percent of its letters with the old one (a name with a capital is not held to that: speech to text writes Siobhan as "shivon"); a day, month or number changed for another is never one. What it sounds like is the word in the entry's `text` (speech to text, after the Vocabulary), found by the pasted word's own spelling or its place in a one-for-one change, never the clean-up's spelling, never an everyday word, never one already listed; a pasted word that cannot be found there gives no suggestion. At most four, names and acronyms first. The baseline is always `styled`, so a second edit is compared with what was pasted.

Window: `logic.js` holds the search (`vocabMatches`, accents folded), the four orders (`VOCAB_SORTS`; `vocabSortRows`), the selection helpers, the import previews (`vocabImportView`, `snippetImportView`), `bytesToBase64`, `finalText`, `isEdited`, `suggestionView`. `app.js` keeps the order in `localStorage` (a convenience, in a try block), one `makeImportPanel` for both imports, and Edit text on `makeCard`. Logs carry counts, file names and exception class names only, never a word.

### S11a Shortcuts

Three keys in `settings.json`, all optional (a file without them reads as the defaults, and an older Waffler ignores them). They are read with `shortcut_settings.settings(stored)` (anything unreadable the default) and written only through `save_settings({...})`, which checks the payload first (`shortcut_settings.settings_problem`, which asks `action_hotkeys.validate` / `cancel_problem`) and writes the canonical form (`shortcut_settings.merged`; a default is removed from the file). A refused payload saves none of what came with it. `get_settings()` carries them as `shortcut_settings.window_view(stored)`: the same keys plus `paste_last_display`, `copy_last_display` and `cancel_display`.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `paste_last_hotkey` | list of key names | `[]` (unset) | The Paste last shortcut, named as the hotkey recorder names keys. A press: it starts when the keys come back up (`ActionHotkeys.register_on_release`), because it types into the app in front. |
| `copy_last_hotkey` | list of key names | `[]` (unset) | The Copy last shortcut. A press, fired when the keys go down. |
| `cancel_key` | str | `"esc"` (key absent) | `"esc"` or an F key `"f1"` to `"f20"`. Read at the start and when the dictation hotkey's listener is rebuilt (`SmartHotkeyListener(cancel_key=)`, `WindowsHotkeyListener(cancel_key=)`), the only thing it changes in either listener being which key the cancel handler watches. |

Transform keeps `transforms.hotkey` and Command mode `command_mode.hotkey`; nothing moved.

The registry (`src/action_hotkeys.py`):

- `ACTIONS` is the one list of the "extra" actions: `transform` (press), `command` (hold), `paste_last` (press), `copy_last` (press), each an `ActionSpec` (`label`, `kind`, `blurb`, `path` to its keys in settings.json, and the `feature` and `feature_path` that must be on for it to count: Transform and Command mode only count when switched on, and a combination saved while the feature is off is still reserved). `saved_shortcuts(stored, skip)` reads all four; `stored_keys`, `feature_on`, `cancel_key_of` read one.
- `validate(action_id, keys, platform, stored, dictation_hotkey=None)` is the one check, used by `transforms.settings_problem`, `command_mode.settings_problem`, `save_settings` for the two new keys, `Api.check_shortcut` (the dialog, live, nothing saved) and the page's conflict sentences. It calls `check(keys, platform, dictation_hotkey, others, hold, cancel_key)`: one letter, number or F key with at least two modifier keys including Control or Command (Control or the Windows key on Windows), except an F key from F1 to F20 pressed on its own or with any modifiers (presses only); never Fn; nothing in `_RESERVED` or `_RESERVED_KEYS` (each with who uses it and for what, so the sentence names it: Command + Space opens Spotlight, and so on); nothing that equals, sits inside or contains the dictation hotkey (the hands-free chord is that and Space, and Space cannot be in a shortcut, so it needs no rule of its own), the cancel key (when it is an F key) or another action's shortcut (named in the sentence, "Another shortcut (Transform)..."); on a Mac with Fn as the dictation hotkey not F1 to F15 (`_FN_BUSY_KEYS`: F1 to F12 are reached by holding Fn, and the dictation hotkey's `FnHandler` treats F13 to F15 as Fn; a new Fn hotkey is refused against shortcuts and a cancel key in the way by `dictation_clash_message`, the cancel key may still be F1 to F12); on Windows no Ctrl with Alt (without the Windows key) with a letter or a number, for any action, and for a hold whatever its key (AltGr). A hold on a Mac may be **modifier keys alone** (two or more, one of them Control or Command, not Fn, not inside or around any other shortcut or the dictation hotkey).
- Swallowing (`swallow_down`, `swallow_up`; `MacComboObserver.handle` and the Windows hook return True). The main key of a registered shortcut is kept from the app, with its repeats and its key-up; modifier keys never are; nothing is swallowed unless the modifiers are exactly the shortcut's, while the dictation hotkey is held (`set_ptt_probe`, learned from the listener in `attach_listener`), or while the key-recording dialog is open (`set_recording`, from `Api.shortcut_recording`; it also stops shortcuts firing, and times out after `RECORDING_MAX_S`). A swallowed key is remembered until its key-up, forgotten after `SWALLOW_STALE_S` without an event for it (checked at every key and modifier event), and a fresh non-repeat press starts clean, so a lost key-up cannot leave a key swallowed. A repeat is recognised by the system's flag on a Mac and, on Windows (which has none), by the key still being remembered. A repeat of a key whose first press went through is never swallowed (it would leave the app with a key-down and no key-up); on Windows a repeat is a key-down of a key `is_swallowing` or `is_held` knows. A key a program posted itself (the paste's Cmd+V) is never swallowed. On Windows, swallowing a key with the Windows key or Alt held would let the Start menu or the menu bar open when it comes up, so `windows_event` is given a `mask` that taps the unassigned key 0xE8 once per press (UNVERIFIED in a real session). A press that starts when the keys come up (`register_on_release`) is dropped, never run late, when its hold goes stale or its action is removed or replaced; Command mode's hold is still ended so its recording stops.
- A hold of modifier keys alone (`modifiers_changed` arms a `MODIFIER_HOLD_S` timer when exactly its modifiers are held; any key down, `other_key_down`, an extra or missing modifier, `unregister` or the dialog cancels it).

The bridge (`app.py`): `get_shortcuts()` (the page: `shortcut_settings.view`, rows with `id, label, kind, description, keys, display, editable, clearable, clear_text, clear_label, enabled, needs, needs_section, conflict`, and `rules`), `check_shortcut(action_id, keys)`, `save_shortcut(action_id, keys)` (empty list clears; each goes through the call that always saved it), `reset_shortcuts()` (clears every shortcut, Esc to cancel, the dictation hotkey to its default; the switches stay), `shortcut_recording(active)`. The dictation listener is rebuilt by `Api._restart_hotkey_listener` (also used by a change of the dictation hotkey), which re-applies Transform, Command mode and Paste last / Copy last (`WafflerPipeline.apply_last_result_shortcuts`) before starting it. `get_hotkey_config()` also carries `cancel_key` and `cancel_display`, which the window uses to name the cancel key in the Journal's live line and the Not sent card. Paste last as a shortcut pastes where the person is (`paste_last(aim_at_last_app=False)`, so on Windows not into the app last dictated into, which is for the tray menu) and, on Windows, waits for the modifier keys to come up (`wait_for_modifiers_up`) before Ctrl+V. Notifier kind `last_result_notice` (a gap of 3 s) carries the busy refusal, "nothing yet" and "Copied". Paste last and Copy last as shortcuts refuse while a dictation, a command or a transform runs; the menu bar items do not, as before.

Window: the page is the old Hotkey section (`data-sec="hotkey"`, nav label Shortcuts), with the dictation hotkey's test and presets below the rows. `logic.js` holds `captureKeyId` (a Windows letter is the key the layout types, which is what the hook hears; a Mac's is the physical key; Esc and Space are recorded only where they mean something), `shortcutRows`, `shortcutRulesView`, `hotkeyDialogText(target, isMac)`, `shortcutSaved`.

### S11b Long takes and double-tap

**The longest take** is 20 minutes (it was 12). `src/take_limit.py` is the one place the figure is written (`MAX_TAKE_S` 1200, `WARN_BEFORE_S` 60); `app.py`'s `_level_loop` asks a `TakeWatch` (clock injected through `WafflerPipeline._take_watch`) once a tick and gets `WARN` once at 19 minutes and `STOP` once at 20 (a clock that jumps past the limit gets the stop and no warning). The warning is notifier kind `long_recording` (INFO, gap 30 s, held 6 s; `user_messages.take_limit_warning()`), the stop is `recording_limit` (`take_limit_stopped(minutes)`), then `on_hotkey_release()` as the hotkey would and `hotkey_listener.reset_state()` where the listener has one (a Mac; the Windows listener has none, so a hands-free take that ran out of time leaves it in its hands-free state and the next press of the combination is absorbed, as it already is after the pill's stop). The loop ends when a newer recording has begun (`_recording_session`), so two loops cannot both warn.

There is still no chunking while recording and no cut by time. What turns a 20-minute take into text is unchanged: `_split_audio_on_silence` cuts a WAV over 18 MB (about 9.4 minutes at 32 KB a second) at pauses into pieces of about 120 s (forced cut at 150 s); 20 minutes is 38.4 MB, about ten pieces. Two fixes ride on it: the suspicious-transcript retry (`_retry_if_incomplete`) used to send the whole clip to the other provider and now sends the same pieces (`_dispatch_pieces`, also the first pass's loop), and it reuses the speech the first pass measured.

| Where | 12 minutes (3.15.1) | 20 minutes |
|---|---|---|
| Speech to text, all attempts together (`pipeline_watchdog.transcribe_deadline_s(audio_s, local=False)`) | 30 s + 0.5 s per audio second, 45 s to 330 s | the same line, 45 s to **660 s** (630 s at 1,200 s); `local=True` (the mlx or faster-whisper backend, `WafflerPipeline._stt_is_local`) has twice every figure |
| "Still working" offer (`offer_after_s`) | `max(8, 0.4 x audio)` | the same, at most **150 s** |
| Clean-up (`STYLE_DEADLINE_S`, and the styler's own `_style_deadline_for`) | 40 s backstop, 30 s cap | unchanged: `tests/test_style_deadline.py` pins the 30 s cap at any length. A 20-minute take is about 3,000 words; if a slow clean-up provider does not finish, the words are pasted as said (never lost), with the usual notice. Owner decision if it matters: let the budget grow past 1,000 words |
| Peak memory above the app at rest while a take is turned into text (synthetic take, fake provider) | 410 MB at 12 minutes (it would have been 700 MB at 20) | 195 MB at 12 minutes, 340 MB at 20, after `_window_rms`, a block-at-a-time lift in `boost_quiet_speech` (same bytes out) and the silence checks letting go of their arrays |

`DictationRun` carries `local_stt`, set before the stage it sizes, so `stage_limit` (what the watchdog's "stuck" check reads) and the `deadline=` passed to `run.call` are the same number. Try again (`resend_unsent`) and Redo (`redo_take`) size theirs from the file's length. Nothing in `quality.assess` scales with length (the words-per-speech-second floor, the 80 % clean-up retention, the dangling-tail check), so a long take is judged by the same rules; `mic_dropout_signal` still needs a dead run of 25 % of the take that reaches its end, so a 20-minute take with scattered pauses is not suspected. Recent audio keeps ten files of any length (up to 380 MB).

**Double-tap to go hands-free** is one key in `settings.json`, `double_tap_handsfree`, a bool, off unless exactly `true` (`double_tap.enabled(stored)`). It is written only through `save_settings({"double_tap_handsfree": bool})`, which refuses anything else (`user_messages.DOUBLE_TAP_UNKNOWN`) before saving any of the payload, and applied at once to the running listener (`WafflerPipeline.apply_double_tap` calls `listener.set_double_tap(bool)`). `get_settings()["double_tap_handsfree"]` and `get_shortcuts()["double_tap_handsfree"]` carry it; the rows of the Shortcuts page (`shortcut_settings.rows`) are unchanged, and the window draws the switch itself under the Hands-free row (`ui/app.js _doubleTapRowHtml`, `logic.js doubleTapView`). "Reset shortcuts" leaves it, as it leaves the other switches. It is not secret and goes into the logs bundle as it is.

What a double-tap is is `src/double_tap.py`'s `DoubleTapGate`, shared by both listeners and tested on its own. A press that ends within `TAP_MAX_S` (0.30 s) of going down is a tap; a tap whose key-down came within `WINDOW_S` (0.35 s), and not within `BOUNCE_S` (0.04 s), of the previous tap's key-up is the second of two. **Nothing is deferred**: the first tap starts and stops a recording exactly as before (the drop of a tap with under 0.15 s of speech, a quick "Yes" still written down, the "Don't tap, hold" hint, which already waits 0.9 s for a second press), and the second press is an ordinary press; at its release, instead of stopping, the listener keeps the take recording and locks it (`_on_lock`: the lock cue, `_hands_free_press_id`, so no hint for that take), the state Space gives. A second press held past `TAP_MAX_S` is push to talk, so tap then hold is today's behaviour. The Mac Fn key reports its release 150 ms late (`_FN_RELEASE_HOLD_S`, its hold-quiet timer), so its gate is given `release_lag_s` and measures taps and gaps as the finger made them; that timer also joins two taps under 150 ms apart into one press, so on Fn the floor between the taps is 0.15 s (not changed: `test_fn_handler_chatter`, `test_hotkey_poll_latch` and `test_windows_hotkey_clear_on_stop` stay as they were).

Per platform, with the setting on (`SmartHotkeyListener(double_tap=, clock=)`, `WindowsHotkeyListener(double_tap=, clock=)`, both `set_double_tap(bool)` and `double_tap_enabled`; with it off `_double_tap` is `None` and no line of either state machine reads it):

- **Mac** (`smart_hotkey.py`): `_on_hotkey_press` starts the gate's press when it starts a take, and in a hands-free take a press ends it (`_press_ends_hands_free`: not when it is the last release bouncing); until now only the hotkey and Space together did on a Mac (Windows always ended it with a press). `_on_hotkey_release` asks the gate; True means `_sticky`, `_locked_by_double_tap`, `_fire_lock` and no release. A take locked by a double-tap can be ended by a press even after the setting is switched off. Esc, `reset_state`, a Space lock and the end of a take forget the taps. A listener made again (hotkey or cancel key changed) has seen nothing.
- **Windows** (`windows_hotkey.py`): the same in `_check_combo_press` / `_check_release` (the keys are not cleared on the lock, as in `_enter_sticky`; a combination press just after a release is bounce), and in the polling fallback.
- Not done, on purpose: extra mouse buttons (low value, a low-level mouse hook is a larger risk).
